# Pre-registration v1

Status: DRAFT — commit this file unchanged before the first paid run; the commit is the timestamp.

This is the full pre-registration for the test split. It fixes the hypotheses, the metrics, the
comparisons, the tests, the margins and the exclusion rules before any test-split result
exists. Repositories are fixed strata: claims are scoped to the repositories in `corpus.yaml`
at the freezing commit and say nothing about repositories in general.

## Corpus and split

The repositories and base commits are those recorded in `corpus.yaml` at the freezing commit.
Items are split into tuning and test by a seeded hash, stratified by repository and family,
with every cluster (the anchor and blind variants of one pull request) kept whole in one slice;
the default tuning share is 20%. The ids of each slice and a SHA-256 of the test file are in
`split.lock.json`. Templates, the rubric and every design choice may be tuned on the tuning
slice only. The test slice is generated once, after this file is committed, and is never read
during tuning; a later edit to a test item fails the lock check.

## Metrics

- **Answer recall** (primary): the share of a change-set item's gold files that appear in the
  `Files:` list of the answer, per item, from 0 to 1.
- **File recall@10**: the share of gold files among the first 10 distinct files of the arm's
  retrieval ranking, per item.
- **Steps to the first gold file**: for agent arms, the number of tool steps before the first
  gold file is touched; an item where none is reached is censored at the run's step count and
  reported with the count of such items.
- **Dollars per question**: metered cost of every model call attributed to the question.
- Rationale and hand-written items are judged by Luna and reported per family; where weighted
  kappa on the 150-label check is below 0.6 for a family, that family's answer-quality numbers
  are reported as exploratory. Grades from any other judge are reported separately.

## Hypotheses

Each has one metric, one pair of arms, one test and one direction, at alpha 0.05 (two-sided
tests at 0.05, one-sided tests at 0.05 in the stated direction). Items are change-set items in
the test slice unless stated otherwise.

| Id | Hypothesis | Metric | Arms (A vs B) | Test | Direction | Holm family |
| --- | --- | --- | --- | --- | --- | --- |
| H1a | `agent` beats `structural_rerank` | answer recall | `agent` vs `structural_rerank` | paired cluster permutation, bootstrap interval | A higher | main |
| H1b | `agent` costs more than 5 times `structural_rerank` per question | dollars per question | `agent` vs `structural_rerank` | one-sided test that the paired difference exceeds 4 times B's mean cost, i.e. the ratio of means exceeds 5; ratio interval by cluster bootstrap | A above 5 times B | main |
| H2 | `structural` beats `hybrid` (neither reranked, so the channels are the only difference) | file recall@10 | `structural` vs `hybrid` | paired cluster permutation, bootstrap interval | A higher | main |
| H3 | Removing co-change lowers recall (the headline) | file recall@10 | `structural` vs `structural_-cochange` | paired cluster permutation, bootstrap interval | A higher | main |
| H4 | `agent` beats `agent_text_tools` | steps to the first gold file | `agent` vs `agent_text_tools` | paired cluster permutation, bootstrap interval | A fewer steps | main |
| H5 | `agent_workers` is equivalent to `agent` | answer recall | `agent_workers` vs `agent` | two one-sided tests (TOST) at alpha 0.05, cluster bootstrap | equivalence within plus or minus 3 points (0.03) | own (not Holm-adjusted) |
| H6 | `hybrid_multiquery` or `hybrid_hyde` closes part of the gap between `hybrid` and `agent`, at a small fraction of the agent's cost | answer recall; dollars per question | each of `hybrid_multiquery`, `hybrid_hyde` vs `hybrid`; gap to `agent` | paired cluster permutation for each arm against `hybrid`; the share of the `hybrid` to `agent` gap closed with its interval; cost as a fraction of the `agent`'s | recall higher than `hybrid`; cost under 25% of `agent` | main (2 tests) |
| H7 | `auto` reaches at least 90% of `agent`'s answer recall at less than half its cost | answer recall; dollars per question | `auto` vs `agent` | recall: the lower end of the 95% interval on the ratio of means is at least 0.9; cost: the upper end of the interval on the cost ratio is below 0.5 | both conditions must hold | main (2 tests) |

H5's null is plausible and the direction is stated honestly: the hypothesis is that the arms are
equivalent, and a result inside the margin is reported as equivalent only when both one-sided
tests reject. A non-significant difference test is never reported as equivalence.

**Holm.** The main family is H1a, H1b, H2, H3, H4, H6 (both tests) and H7 (both tests), at a
family-wise alpha of 0.05; the corrected p-values and decisions are reported. H5 is a separate
equivalence test at its own alpha of 0.05. Every other comparison in the report is labelled
exploratory and is outside both.

## Tests

- **Pairing.** Every arm runs on every test item, so every comparison is paired.
- **Intervals.** 95% percentile bootstrap, 10,000 resamples, resampling clusters with
  replacement within each repository; repositories are fixed and not resampled.
- **Permutation tests.** Paired sign-flip tests at the cluster level, 10,000 patterns (or every
  pattern when there are at most 10,000), add-one smoothing when sampled.
- **Equivalence.** TOST by the same cluster bootstrap, margin plus or minus 0.03 on answer
  recall.
- **Rates.** Wilson 95% intervals on every rate (errors, format failures, exclusions, routes).
- **Per-repository direction.** Counts of which arm leads in each repository are descriptive
  and carry no significance.
- **Minimum detectable difference.** Reported per comparison from the observed paired variance:
  `(z_{0.975} + z_{0.8}) * SE`, with `SE` the standard deviation of the cluster-mean paired
  differences over the square root of the number of clusters.
- **Pareto frontier.** Dollars per question against answer recall over all arms, with `auto`
  included; descriptive.
- **n.** Every number is reported with the number of items and clusters it rests on.

## Exclusion rules

- **Error records.** A generation that ended in an error, including a degraded reranker and a
  flagged `read_file` unavailability, is excluded from the comparisons involving its arm and
  listed with arm, item and reason. The error rate per arm is reported with a Wilson interval.
- **Format failures.** An answer with no parseable `Files:` list is scored 0 and counted; the
  format-failure rate is reported separately per arm.
- **Ambiguous gold.** Items the hand check marks ambiguous are dropped before generation and
  listed.
- **Budget stop.** Items an arm did not reach because the run hit its cap are excluded from its
  comparisons and listed; nothing is imputed.
- **Run variance.** Repeat runs on the variance subset are reported as run-to-run variation and
  never pooled into the paired comparisons.
- **Nothing else.** No item is removed after results are seen, and no hypothesis, metric or
  margin is added or changed after this file is committed; anything further is exploratory.
